# Genesis × 強化学習で四足ロボット Go2 にバク転を覚えさせる

物理シミュレータ [Genesis](https://github.com/Genesis-Embodied-AI/Genesis) と強化学習（PPO）を使い、四足ロボット Unitree Go2 にバク転を学習させました。
Genesis には Go2 がバク転する学習済みモデル（お手本）は入っていますが、**どう学習させたかのコードは公開されていない**ため、報酬（ロボットに与える点数）と学習スクリプトを自作して、ゼロから学習させています。
ローカルに環境を作らず、**Google Colab（T4 GPU）だけで**学習から動画作成まで完結させています。

## 結果

| | ノートブック | 学習回数 | 学習時間（T4） | 結果 |
|---|---|---|---|---|
| 歩行（公式サンプル） | `01_go2_walking.ipynb` | 300 回 | 約 4 分 | 前に歩けるようになった |
| バク転 v1（最初の報酬） | `02_go2_backflip_v1.ipynb` | 1000 回、5001 回 | 約 1 時間（5001 回） | 高く跳ぶようにはなったが、1/4 回転して元に戻る動きに収束し、失敗 |
| **バク転 v2（報酬を改善）** | `03_go2_backflip_v2.ipynb` | 5001 回 | 約 1 時間 8 分 | **200 回目（約 3 分）で 1 回転に成功**。その後、着地も安定 |

バク転 v2 の学習の過程（動画で確認した様子）:

| 学習回数 | 動き |
|---|---|
| 100 回目 | 半回転して転ぶ |
| 200 回目 | 1 回転できたが、着地できずに転がっていく |
| 5000 回目 | 1 回転して足から着地できる。着地後の震えもなくなったが、姿勢は少し不自然 |

学習ログから見た経過（回転量・着地の報酬が、それぞれの満点に対して何 % もらえているか。ログの値から換算した推定値）:

| 学習回数 | 回転量の報酬 | 着地の報酬 | 平均報酬 |
|---|---|---|---|
| 0 | 1 % | 0 % | -0.25 |
| 100 | 46 % | 0 % | 7.0 |
| 200 | 95 % | 50 % | 10.8 |
| 1000 | 89 % | 62 % | 13.2 |
| 2000 | 99 % | 97 % | 19.1 |
| 5000 | 99 % | 98 % | 20.7 |

> 換算方法: 回転量の報酬は「回った角度 ÷ 360 度」で最大 1、着地の報酬は 1 回転しきったときだけもらえるので、ログの値をそれぞれの理論上の最大値で割っています。

v1 では 5001 回学習してもたどり着けなかった動きに、v2 では 200 回目でほぼたどり着いています。

## 環境

- Google Colab（Tesla T4、High-RAM）。VS Code の Colab 拡張から接続
- Python 3.13
- `genesis-world` 1.4.5
- `rsl-rl-lib` 5 系（PPO の実装）
- 並列環境数 4096（GPU 上で 4096 台の Go2 を同時にシミュレーション。台どうしは干渉しない）

## Colab で環境を作るときに詰まった点

参考にした記事（[Genesis を Google Colab で試す](https://tototototototo7.hatenablog.com/entry/2025/genesis_test_google_colab)）は古い Genesis（0.2 系）が前提だったため、最新版（1.4.5）では以下の対応が必要でした。

| 症状 | 原因 | 対処 |
|---|---|---|
| `Please install 'rsl-rl-lib>=5.0.0'` | Genesis 1.4.5 のサンプルは rsl_rl 5 系が必要（記事は v1.0.2） | `go2_train.py` から必要なバージョンを読み取ってインストール |
| `unrecognized arguments: -B ... --max_iterations` | 学習スクリプトのオプション名が変わっていた | `-b` と `--max-iterations` に変更 |
| エラー表示なしで学習が終了（`Segmentation fault`） | Colab に EGL（画面のない環境での描画）用の NVIDIA の設定ファイルがない | `/usr/share/glvnd/egl_vendor.d/10_nvidia.json` を作成（MuJoCo の公式 Colab チュートリアルと同じ対処） |
| 録画で `stop_recording() got an unexpected keyword argument` | 録画 API の変更（保存先と fps は `start_recording()` で指定し、フレームは自動で記録される） | 新しい API に合わせて修正 |

## バク転の学習の仕組み

### 強化学習の流れ

- **方策**（ロボットの脳にあたるニューラルネットワーク）が、**観測**（体の傾き・回転の速さ・関節の角度など 60 個）を受け取り、**行動**（12 個の関節の目標角度）を出力する
- 0.02 秒ごとに観測と**報酬**（点数）を確認し、点数が多くもらえる動き方に方策を少しずつ近づける（PPO）

### 環境

公式の `go2_backflip.py`（学習済みモデルを動かすためのスクリプト）の設定を流用しています。

- 1 エピソード 2 秒
- 体が傾いてもエピソードを打ち切らない
- 観測に「エピソード内の経過時間」を含める。ロボットが「今は踏み切りの時間」「今は回転の時間」と判断できるようにするため
- 歩行と違い、エピソードは毎回最初（踏み切りの前）から始める

### 最初の報酬（v1）

2 秒を 3 つの区間に分けて、区間ごとに違う動きに点数を付けます。

| 時間 | 段階 | 報酬 | 重み |
|---|---|---|---|
| 0.4〜0.8 秒 | 踏み切り | 上向きの速さ（`jump`） | 2.0 |
| 0.5〜1.1 秒 | 空中で回転 | 後ろ向きに回転する速さ（`ang_vel_y`） | 1.0 |
| 1.3 秒〜 | 着地 | 立ち姿勢の高さ（0.3 m）に近いほど（`landing_height`） | 2.0 |
| 全体 | | その時刻の目標の姿勢に近いほど（`orientation_tracking`）。目標は 0.5〜1.1 秒で 1 回転する | 5.0 |
| 全体 | | 横回転・ひねり（`ang_vel_xz`）、関節の速すぎる動き（`dof_vel`）、急な動作の変化（`action_rate`）へのペナルティ | -0.1 / -0.0001 / -0.01 |

**結果と考察:** 1000 回、5001 回と学習を進めても、1/4 回転ほどして元の姿勢に戻る動きに落ち着きました。
v1 では、回りきれずに元の姿勢に戻っても、着地の報酬（立ち姿勢の高さ・まっすぐ立つ姿勢）が満点でもらえました。1 回転に挑戦して転ぶより「少し回って戻る」ほうが確実に点数を稼げるため、ロボットはそちらを選んでいたと考えられます。また、回った角度や跳んだ高さを直接は評価しておらず、「惜しかった」ことが報酬に表れませんでした。学習回数を増やしても改善しなかったので、問題は学習時間ではなく報酬の与え方にあったと判断しました。

### 改善した報酬（v2）

v1 から次の 3 か所を変えました。

| 報酬 | 変更 | ねらい | 重み |
|---|---|---|---|
| `landing_height` | 条件付き | 1 回転しきったときだけ着地の点数を与える。少し回って戻っても得をしない | 2.0 |
| `flip_rotation` | 追加 | 1.1 秒以降、回った角度に応じて点数（180° で半分、360° で満点）。惜しかったことも評価する | 3.0 |
| `flight_height` | 追加 | 0.5〜1.1 秒、胴体が立ち姿勢より高いほど点数。1 回転に必要な滞空時間を稼ぐ | 5.0 |

- `orientation_tracking` も、回転の時間が過ぎた後は 1 回転しきった場合だけ与える
- 回った角度は、胴体が 0.25 m 以上の高さにあるときだけ数える（地面の上で転がるでんぐり返しを数えないため）
- 回った角度の合計が 306 度（1.7π）以上なら「1 回転しきった」とみなす

その結果、200 回目のモデルで 1 回転できるようになりました。「惜しかった」動きにも点数を付けたことで、少しずつ回転量を増やす方向に学習が進んだと考えられます。
ただし 3 か所を同時に変えたため、どの変更が最も効いたかは切り分けられていません。

## わかったこと

- 学習にかける時間だけでなく、報酬をどう設計するかが重要。v1 は 5001 回学習しても 1 回転できなかったが、v2 は 200 回目（約 3 分）で 1 回転できた
- ロボットが楽な報酬の稼ぎ方に収束しないように、ゴールを達成したときだけ点数を与えるなどの条件付けが必要
- ゴールの達成だけでなく「惜しかった」動きにも点数を付けると、学習が進みやすい

## 今後の課題

- より綺麗なバク転のために、足の動き（関節の姿勢や足の接地）に関する報酬を設計する
- 3 つの変更を 1 つずつ外して学習し、どの変更が効いたのかを確かめる
- 強化学習で、より長期的なタスクに取り組む

## 再現手順

3 つのノートブックはそれぞれ独立していて、どれか 1 つだけを実行することもできます。

1. ノートブックを Google Colab で開き、ランタイムを **T4 GPU** にする（VS Code の場合は Colab 拡張で接続し、カーネルは Python を選ぶ）
2. 1 章（インストール、EGL の設定）と 2 章（Google Drive。保存しない場合は `USE_DRIVE = False`）を実行する
3. 以降の章を上から順に実行する

| ノートブック | 内容 |
|---|---|
| `01_go2_walking.ipynb` | 公式の `go2_train.py` で歩行を学習し、動画を作る |
| `02_go2_backflip_v1.ipynb` | v1 の報酬でバク転を学習し、動画を作る |
| `03_go2_backflip_v2.ipynb` | v2 の報酬でバク転を学習し、動画を作る |

バク転のノートブックの流れ:

- 3 章: `%%writefile` のセルで、報酬・学習・録画のスクリプトを Colab 上に作る
- 4 章: 公式の学習済みモデル（お手本）の動画を見る（任意）
- 5 章: 学習する（`BF_MAX_ITER = 5001` で約 1 時間。モデルは 100 回ごとに保存されるので、5001 にすると `model_5000.pt` まで残る）
- 6 章: 動画を作る。6-2 では 100 回ごとのモデルをまとめて録画し、学習の過程を見比べられる

学習結果は `examples/locomotion/logs/<実験名>` に保存され、Drive を使う場合は `MyDrive/pai_finalwork/` にもコピーされます。同じ実験名で学習し直すと前の結果は消えるので、設定を変えたときは名前も変えてください。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `01_go2_walking.ipynb` | 歩行の学習と評価 |
| `02_go2_backflip_v1.ipynb` | バク転・最初の報酬（v1）の学習と評価 |
| `03_go2_backflip_v2.ipynb` | バク転・改善した報酬（v2）の学習と評価 |
| `pai_finalwork.ipynb` | 作業中に使っていたノートブック（歩行とバク転 v2 を 1 つにまとめたもの） |
| （生成）`go2_backflip_v1_env.py` / `go2_backflip_v2_env.py` | バク転用の環境と報酬 |
| （生成）`go2_backflip_train.py` | 学習スクリプト（`--env` で使う報酬を指定する） |
| （生成）`go2_backflip_record.py` | 動画作成スクリプト（お手本、指定したモデル、複数のモデルをまとめて） |

（生成）のファイルは、ノートブックの `%%writefile` のセルから Colab 上の `Genesis/examples/locomotion/` に作られます。
Genesis のリポジトリにある `go2_env.py`・`go2_train.py`・`go2_backflip.py` は書き換えず、読み込んで使っています。
